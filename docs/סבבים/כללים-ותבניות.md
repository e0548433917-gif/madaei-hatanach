## ⭐ הוראה מחייבת — בסוף כל סבב

**כל מודל שעובד על הפרויקט הזה חייב, בסיום כל סבב, לפני שהוא מסיים את התשובה:**

1. **לעדכן את שני קבצי התוכנית** — לסמן ✅ במקום ⬜ על מה שנסגר, ולרשום מה נשאר פתוח.
2. **לתת בלוק מוכן להעתקה** בפורמט הזה בדיוק:
3. 🆕 **כל סבב רציני (לא תיקון קטן) מסתיים ב-`build/pack.ps1 -Release`** — commit + תג `v<version>` + push + GitHub Release עם החבילות. **לא להשאיר עבודה גמורה רק בעץ המקומי בלי Release.** נקבע 9.8.26.
4. 🆕 **לפני `git commit` — להריץ `git status` ולוודא שאין קבצים לא-צפויים** ששיחה מקבילה אחרת שינתה/יצרה (יש כמה שיחות שיכולות לרוץ על אותו עץ עבודה בו-זמנית). **להוסיף לקומיט רק את הקבצים שהשיחה הזו עצמה נגעה בהם**, ולא לגעת/לדרוס קבצים של שיחה אחרת שעדיין לא סיימה. נקבע 9.8.26, בעקבות התנגשות בפועל סביב `guides/talmud-tools/`.
5. 🆕 **לבדוק GitHub Issues פתוחים** (`gh issue list`) ולוודא שהם מוזכרים בתוכנית — לא לתת לדיווח אמיתי מהתוסף (למשל Issue #1, ״הסמלים בפנים עדיין אותו דבר״ = 4.8) ליפול בין הכיסאות. מי שמקבל הרשאת כתיבה לריפו (כגון שותף חיצוני) יכול לראות ולהכריע בעצמו. נקבע 9.8.26.
6. 🆕 **ברגע שכל התוכנית הפעילה נסגרת (3.0.0 + ט׳ + סבב ת׳) — לא לעצור.** לפתוח מיד ״סבב שכלול״: לעבור על כל הפרויקט מחדש ולחפש מה אפשר לשפר (ביצועים, UX, כיסוי תוכן, באגים שלא דווחו) ולהציע רשימה חדשה. נקבע 9.8.26.
7. 🆕 **`pack.ps1 -Release` עם `-Notes` חייב לכלול תבליט לכל סבב שממתין לשחרור — לא רק לסבב שיזם את ההרצה.** נמצא 12.8.26: ד.1ב (חולין) וד.1ג (סוכה ולולב) הצטברו בעץ המקומי בלי Release (כלל 3), ואז שיחה שתיקנה תקלת התקנה דחופה הריצה `pack.ps1 -Release` עם `-Notes` שתיאר **רק** את התיקון שלה — הקוד של שני הסבבים נארז ונשלח בפועל, אבל ה-CHANGELOG (ולכן גם לשונית ״מה חדש״ בתוסף) לא הזכיר אותם כלל. **לפני כל `-Release`: `git log` מאז התג הקודם ולוודא שכל סבב ✅ שם מיוצג בתבליט משלו ב-`-Notes`**, גם אם הוא לא הסיבה להרצה הנוכחית.

8. 🆕 **מדריך/כרטסת עזר חדשים נבנים עם איקון תמונה מלכתחילה, לא אמוג׳י.** נקבע 12.8.26 בסיום 4.8. הקטגוריה החדשה נרשמת ב-`CATEGORIES` (`shell/core.js`) **וגם** ב-`CAT_ICON_IMG` שמעליה, עם קובץ ב-`icon/cats/<id>.png` (או `icon/masechtot/<מסכת>.png` לכרטסת מסכת). שדה `icon` האמוג׳י נשאר כנתיב-נפילה בלבד — `catIconHtml()` נופלת אליו כשאין קובץ או כשהטעינה נכשלת. **אין להוסיף אמוג׳י קטגוריה ישירות בקוד תצוגה** (צ׳יפים, שורות תוצאה, כותרת מדריך, ״מוזכר יחד עם״) — תמיד דרך `catIconHtml(catId, size)`, שהוא מקור האמת היחיד. היוצא מן הכלל היחיד: הפופאפ של אוצריא (`ui.showConfirm` ב-`bridge.js`/`background.js`) הוא **טקסט בלבד** ואינו יכול להציג תמונות, ולכן שם האמוג׳י נשאר בכוונה.

```
▶ הסבב הבא: <מספר ושם>
▶ לפתוח ב: <Opus / Sonnet / Claude Code / Gemini>, שיחה חדשה
▶ להדביק בשיחה החדשה:

<בלוק הטקסט המלא להדבקה>
```

## 📋 תבנית פתיחה — להעתיק לכל שיחה חדשה

```
תוסף אוצריא ״עינים למקרא״, גרסה X.Y.Z.

אנא בצע את סבב <N> כפי המפורט בקבצי ההוראות בתיקייה:
  שדרוג 3.8\תוכנית-עבודה-תמונך-3.0.md
  שדרוג 3.8\חלוקה-לשיחות-פשוטה.md

הפרויקט: Downloads\תוספי תנך ותלמוד\madaei-hatanach — ריפו git.
המשימה: <מספר המשימה> בלבד. אל תיגע בשום קובץ אחר.

בסוף תן לי:
  (א) diff / רשימת הקבצים ששונו
  (ב) שורת changelog
  (ג) מספר הגרסה החדש
  (ד) את ההוראה לסבב הבא בפורמט המחייב
```

> **הערה למי שעובד ב-Claude Code:** אין צורך ״להעלות״ קבצים — הוא קורא מהדיסק ישירות. עמודת ״מעלים״ רלוונטית רק לשיחות באתר או באפליקציה.
