## ⚠️ קרא את זה קודם — כאן עובדים כמה אנשים במקביל

הריפו אינו של מפתח יחיד. שניים יכולים לערוך את אותו קובץ באותה שעה, וזה כבר קרה
בפועל יותר מפעם אחת. ארבעה כללים שמונעים דריסה:

1. **`git status --short` לפני שנוגעים בכלום.** שינויים שאינם שלך = **מישהו עובד
   בעץ הזה ברגע זה.** אל תקמט אותם, אל תעשה להם `stash`, אל תדרוס. עבוד סביבם.
2. **לעולם לא `git add -A` ולא `git commit -a`.** רק `git add <הקבצים שלך>`,
   בשמות מפורשים.
3. **`git pull --rebase` לפני כל `push`**, לא אחרי שנכשל.
4. **ענף משלך:** `git switch -c work/<נושא-קצר>`, ומיזוג ל-`main` בסוף יחידת עבודה.

הפירוט המלא — כולל שלוש מלכודות שכבר עלו כאן ביוקר (הענף המקומי אינו בהכרח
`main`; `main` המקומי עלול להיות נטוש ולפגר בעשרות קומיטים; `pull --rebase` נכשל
על עץ מלוכלך) — נמצא ב-[`CLAUDE.md`](../CLAUDE.md), בסעיפים ״בתחילת כל שיחה״,
״מדיניות ענפים״ ו״מלכודות ידועות״. **חובה לקרוא לפני הקומיט הראשון.**

### ⚠️ לפני שנועלים ליין — לבדוק מה כבר תפוס

**שניים על אותה משימה = עבודה כפולה שאחת ממנה תימחק.** לפני שמתחילים:

```bash
git branch -r                       # ענף work/<נושא> פתוח = מישהו עליה
git log --all --oneline -25         # קומיטים אחרונים בכל הענפים
gh issue list --state open          # כולל הצהרות "עובד על:"
```

ואז **להצהיר**, כדי שהבא אחריך יראה:

```bash
gh issue create --title "עובד על: <המשימה>" --body "<שם> · ענף work/<נושא> · החל <תאריך>"
```

**המשימה תפוסה? קח את הבאה בתור. אל תיתקע ואל תחכה** — אם יש חפיפה חלקית, השתלב:
קח תת-משימה נפרדת מתוך אותו סבב, ותאם ב-Issue של מי שכבר עליה. עצירה והמתנה
לתשובה היא הדבר היחיד שאסור כאן.
