## מבנה `shell/` — סדר הטעינה קריטי

`index.html` טוען את שנים-עשר הקבצים כ-`<script>` רגילים, **בסדר הזה בדיוק**:

```
core → data → identify → refs → guides → entry-detail
     → edit-forms → results-ui → home → personal → settings → bridge
```

* **`core.js` ראשון** — קבועים, מטמונים וכלים שכל השאר נשענים עליהם.
* **`bridge.js` אחרון** — הגשר לאוצריא, והוא זה שמריץ את האתחול בפועל.
* **בכוונה לא `type="module"`.** כל הקבצים חולקים scope גלובלי אחד; מודולים היו שוברים את כל ההפניות ביניהם.

⚠️ **קוד שרץ בזמן טעינה חייב להימצא אחרי מה שהוא צורך.** למשל `DIVINE_NAME_RE` ב-`core.js` נבנה בזמן טעינה ותלוי ב-`PREFIXES` — ולכן `PREFIXES` יושב ב-`core.js` ולא ב-`identify.js` שנטען אחריו.

**`identify.js` הוא טהור בכוונה** — בלי DOM ובלי `Otzaria` — כדי שאפשר יהיה להריץ אותו ב-Node מול סט בדיקות.

## בנייה

```powershell
pwsh -File build\pack.ps1
```

מעלה את הגרסה ב-patch ואורז שני תוצרים ל-`dist/`: `.otzplugin` להתקנה באוצריא, ו-zip עצמאי לפתיחה בדפדפן רגיל. להריץ בלי העלאת גרסה: `-NoBump`.
`dist/` אינו במעקב גיט — גרסאות מופצות עולות כ-Release.

## פיתוח

```powershell
pwsh -File _serve.ps1 -Port 8933
```

פותח שרת מקומי. רוב התוסף עובד בדפדפן רגיל; מה שדורש `Otzaria` (זיהוי מהספרייה, אחסון קבוע, ערכת נושא) מדולג בבטחה.

הקוד והנתונים הם עבודתו של המחבר. הערכים נכתבו מחדש מתוך מקורות; ציטוטים מובאים עם ייחוס.
